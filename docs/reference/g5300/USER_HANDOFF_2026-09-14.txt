AUTO

Dla stock-like AUTO:

rider_power = calculate_rider_power(
    effort_envelope,
    cadence
);

assist_ratio =
    auto_ratio(
        rider_power,
        base_ratio,
        max_ratio,
        reference_power
    );

motor_power =
    rider_power * assist_ratio / 100;

Przykładowo:

Base Ratio        1%
Max Ratio         525%
Reference Power   200 W

i około:

0 W   →   1%
50 W  → 132%
100 W → 263%
150 W → 394%
200 W → 525%

Potem już normalna konwersja EVistDrive:

motor power
→ phase Iq

Nie kopiowałbym drugi raz stockowego power/cadence → current-like, skoro EVistDrive ma własną fizyczną konwersję.

Czy da się wyrzucić część obecnego kodu?

Tak — ale dopiero po audycie consumerów.

min-Iq hold

legacy assist_dynamics
historyczne workaroundy rider-demand

Nie znaczy to „wywalić wszystko od razu”.

To jest najlepszy sposób, żeby nie powtórzyć sytuacji, w której częściowy port rozwala zachowanie całego silnika.

Moja odpowiedź więc brzmi: tak, zdecydowanie.

Co więcej, po tym reverse mamy już wystarczająco dużo, żeby nie portować kawałków G5300, tylko zaprojektować czysty EVistDrive Ride Pipeline v3, który zachowuje najlepsze mechanizmy stocku, ale pasuje do szybkiego prądowego FOC EVistDrive.

Nie kopiowałbym stocku bit-po-bicie tam, gdzie jego architektura wynika z innego kontrolera. Kopiowałbym zachowanie i matematykę rider-intent, a pozostawił obecny szybki Iq → PI → FOC.

I właśnie z takiego podejścia może powstać znacznie czystszy tor niż obecny.
